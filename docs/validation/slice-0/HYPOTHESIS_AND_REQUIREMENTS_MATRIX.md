# Hypothesis and requirements matrix

Every hypothesis Slice 0 tests, where it comes from, how it is tested, what evidence
counts, which metric reads it, the pass and fail rule, the risk it bears on and the
product decision it affects. Metric IDs (`M-nn`) are defined in `SLICE_0_SCORECARD.md`
§3; hard stops (`HS-nn`) in §4 of the same file.

## 2. Hypotheses

Evidence codes: **I** structured seller interview record (`SI-###`) · **W** workflow
scorecard row (`WF-###` of an `SW-###`) · **B** buyer scorecard row (`BM-###` moderated
or `RC-####` real) · **C** channel evidence row (includes `FI-###` placements) · **N**
incident log · **E** manifest-hashed artefact (redacted screenshot, timing log, copy
versions). Cohorts are defined in `README.md` §2a.

## 3. Canonical funnel hypotheses carried through unchanged

These are not new hypotheses; they are the canonical Slice 0 measures restated so the kit
cannot lose them.

| Canonical measure | Where computed | Band |
|---|---|---|
| Page-open rate (link sent → page opened) | M-19 | above 40% proceed; 20 to 40% proceed with higher-value launch segment; below 20% stop and reopen D-02 |
| Code-entry completion as a share of page opens | M-09 | below 50% stop or rework; 50% to 79% revise and rerun; 80% or higher clean pass |
| Conversation-start rate (code entered → first message) | M-20 | reported; no canonical band |
| Messages per conversation; conversations per listing | M-21 | `ASM-04` falsifier: median under 3 |
| Share of buyer messages mentioning a price | reported in M-12 notes | informs the escalate-on-price-mention design (`AI-031`), no band |
| "Is this a scam?" incidents per hundred replies | M-11 | `RISK-05` signal, no band |
| Marketplace enforcement events | M-18 | any removal is a channel evidence row, not a percentage |
| Verified surface on two primary channels | C rows | Test 1 pass rule |
